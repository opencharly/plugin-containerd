# 2026.295.1321 — feat(engine)!: serve engine:containerd after the spec engine-word cutover

## Summary

Hard cutover of this engine plugin to the spec vocabulary landed in
`opencharly/spec v0.2026295.1243` (`spec#266`): `nerdctl` is deleted from
`#EngineName` (now `podman | docker | containerd`), and `containerd` is driven
through the nerdctl CLI named by the CUE-owned `#EngineBinaries` map.

- **Provider words:** `engine:containerd`, `verb:containerd`,
  `command:containerd`. The dispatch word is `containerd`; `nerdctl` survives
  ONLY as the CLI binary (`spec.EngineBinaries["containerd"]`), never as an
  engine word. No alias, no dual spelling.
- **`start_plan` always names a runtime handler.** An empty `runtime` is filled
  with `crun` and validated against the capability's `runtime_handlers`, so the
  argv always carries `--runtime`. nerdctl's unqualified default handler is
  `runc` while the CRI default is `crun`; the plan never relies on a default.
- **Rootful is IMPLEMENTED at the start-plan boundary.** A rootful request is
  first checked against `supports_rootful`, then prefixed with the capability's
  `privilege_prefix` (`sudo -n`) as argv words from the spec table, and the
  mode-specific `workload_user_rootful` fact applies. A rootful request is never
  silently run as rootless.
- **`unit_emit` is a pure renderer, and the envelope carries no scope field.**
  It renders a user unit from the `start_argv` it is given. A rootful unit
  therefore carries the privilege prefix and `--runtime` when the caller passes
  the rootful start-plan argv; this provider does not re-apply the policy at the
  unit boundary. The boundary is stated in `schema/plugin.cue`, the candy
  description, the skill body and `README.md`, and covered by a test.
- **Defaults are not re-spelled.** No `--address` / `--namespace` is emitted for
  the capability defaults; a caller's override rides `extra_args` through the
  pure body unchanged.
- **Capability row** is served by the one spec body (`describe`): tests assert
  `supports_rootless`, `supports_rootful`, `workload_user_rootless` (`"0"`),
  `workload_user_rootful` (empty), `address`, `namespace` (`default`),
  `privilege_prefix`, `substrates: ["pod"]`, `runtime_handlers`
  (crun/krun/runc/nvidia) and the `#EngineBinaries` binary (`nerdctl`).
- **Skill source:** the skill BODY is `.agents/skills/plugin-nerdctl/SKILL.md`
  (the one canonical base the corpus reader resolves); the candy's
  `plugin-nerdctl-skill:` entity is the owner registration (name/family/owner
  only) and carries no body. `AGENTS.md`, `README.md`, the skill body and the
  candy file all state the same split.
- **Deps:** `spec` -> `v0.2026295.1243`; `sdk` -> `v0.2026294.1520` (the
  previous sdk does not compile against the new spec: six undefined
  `spec.Kubernetes*` aliases, measured). The `go 1.26.8` directive follows the
  sdk's own declaration.
- **Tests:** `containerd_engine_test.go` covers the served words, the
  word/binary split from data, the always-named runtime, the no-default-flags
  rule with its override arm, the rootful prefix, the unit_emit renderer (with
  an unprefixed control proving no re-application), the capability row, and a
  real out-of-process go-plugin round trip (host-builds `./cmd/serve`).
