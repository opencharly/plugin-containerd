# 2026.297.0553 — fix(plugin): address the merged PR non-blocking review notes

## Summary

Follow-up to the three **non-blocking observations** in the merged
`opencharly/plugin-containerd#14` validator verdict (PASS, comment
`6380339133`). Per R1 a finding raised on the PR is fixed or rebutted, never
filed away; this PR fixes all three.

1. **`runtimesFromCRIConfig` was order-fragile.** It returned the FIRST
   object-valued `runtimes` map found. Go map iteration is randomized, so a
   document carrying two such maps could return a different handler set per run.
   It now accumulates the **union** of every `runtimes` map and returns it
   **sorted**, so the answer is independent of map order and of how many maps
   cri-tools nests. New test `TestVerbRuntimesIsOrderIndependent` runs both
   nesting orders 20 times and asserts one sorted answer, plus the empty case.
2. **`verbImage` carried a dead `Descriptor.Digest` field** it never read;
   removed.
3. **The R4 wording was loose** ("with only `charly`/`go`"): `go generate ./params`
   invokes `params/gen.sh`, which needs the `cue` binary. `AGENTS.md` now says so
   explicitly and separates the dev-time codegen step from build/test/`box
   validate`, which need only `go` and `charly`. (The merged PR body cannot be
   edited into the changelog, so the correction lands in the repo's own guidance.)
